# 核心玩法策划案：跨城镇生活模拟 RPG

> 写给现在的我和以后的我。  
> 这份文档的目的不是做宣传稿，而是固定设计方向、玩法边界和实现顺序，避免之后功能越加越散。

## 0. 当前结论

这个游戏不应该只是“星露谷式赚钱 + AI NPC”，也不应该只是“开放世界战斗 RPG + 城镇背景”。它的核心卖点应该是：

**玩家在一个真实运转的地区社会里，从一个落脚点开始谋生、建立关系、积累资产、探索荒野，并逐渐进入多个相互关联的城镇网络。**

NPC 系统是核心。赚钱、委托、战斗、大世界、资产、交通工具，都应该服务于“活着的城镇”和“可被玩家改变的人际网络”。

## 1. 一句话定位

一个 2D 像素风生活模拟 RPG。玩家继承城镇 A 的旧房子，从接委托、战斗、交易和社交开始生活，逐步获得金钱、名声、交通工具和跨城镇资产，并在城镇 A、荒野道路、城镇 B 以及更多地区之间建立自己的生活网络。

## 2. 设计支柱

### 2.1 城镇是活的

每个城镇不是任务大厅，而是一个有居民、职业、日程、地点状态、传闻、关系和经济需求的社会系统。

玩家进入一个城镇时，不是在进入“下一关”，而是在进入新的社会环境。

### 2.2 NPC 不是功能按钮

NPC 有自己的生活、记忆、职业、偏好、关系和当日目标。玩家可以影响 NPC，但不能把 NPC 当作完全服从的工具。

NPC 的行为应该由以下因素共同决定：

- 当前任务和日程
- 感知到的外界信息
- 与玩家和其他 NPC 的关系
- 记忆、事实记录和承诺
- 所在地点能提供的活动
- 当前身体状态、情绪和风险

### 2.3 玩家需要现实动力

玩家要有清晰的行动理由，而不是只为了测试 NPC。

主要动力：

- 赚钱
- 修缮和扩建落脚点
- 买交通工具
- 获得装备和物资
- 建立关系网
- 解锁跨城镇机会
- 影响城镇事件

### 2.4 荒野和战斗服务于城镇

战斗不是独立刷怪系统。荒野、危险和战利品应该反过来影响城镇：

- 战利品可以出售或交付委托
- 受伤会影响玩家和 NPC 对风险的判断
- 荒野事件会产生传闻
- 道路安全影响城镇间交易
- 资源短缺会改变商品价格和 NPC 日程

### 2.5 多城镇不是关卡制

城镇 B 不是城镇 A 的“第二关”。多个城镇应该同时存在于世界网络里。

城镇之间应该有：

- 贸易关系
- 人际关系
- 消息传播
- 物价差异
- 地方委托
- 交通成本
- 风险路线
- 可回流的事件后果

## 3. 玩家起点

玩家开局位于城镇 A，拥有一处落脚点。

推荐设定：

- 爷爷或亲人遗留的旧房子
- 房子可以睡觉、存物、整理物资
- 初期空间小，设施破旧
- 玩家没有稳定收入
- 城镇里有人认识这栋房子，但不一定认识玩家

这个起点的作用：

- 给玩家一个安全归属点
- 给时间循环一个落点
- 给资产系统一个第一目标
- 给 NPC 社交提供自然话题
- 给城镇 A 绑定情感意义

## 4. 主循环

### 4.1 单日循环

1. 起床，查看时间、天气、日历、消息、昨日结果。
2. 在城镇 A 活动：接委托、购物、打工、社交、调查传闻。
3. 选择是否离开城镇：去荒野、道路、资源点或其他城镇。
4. 执行行动：战斗、采集、运输、谈判、救助、送货。
5. 回到落脚点或临时住处。
6. 夜晚结算：金钱、物资、伤病、记忆、城镇事件、NPC 次日计划。

### 4.2 周循环

周循环用于制造“生活节奏”：

- 某些店铺每周休息
- 周末餐厅更热闹
- 周一公告更新
- 每周集市
- NPC 固定拜访、采购、工作交接
- 玩家每周账单或维护费用

### 4.3 月循环

月循环用于制造“经营压力”：

- 房屋维护费
- 车库或交通工具维护费
- 贷款或债务
- 商铺租金
- 月度委托结算
- 商品价格波动
- 城镇声望评级

### 4.4 季节循环

季节用于改变环境和长期策略：

- 不同荒野资源
- 不同怪物和危险
- 不同节日
- 不同 NPC 日程
- 不同贸易需求
- 路线通行状态变化

## 5. 推进结构

### 5.1 阶段一：城镇 A 扎根

玩家目标：

- 熟悉基础操作
- 认识核心 NPC
- 获取第一批委托
- 获得基础收入
- 修复落脚点的基础功能

典型玩法：

- 帮 Jack 送餐或收集食材
- 帮 Tom 找药材或传递病情
- 帮 Alice 调解或传话
- 帮 Len 处理畜牧工场问题
- 在荒野边缘打小型敌人，卖材料

### 5.2 阶段二：荒野和道路

玩家目标：

- 获得城镇外资源
- 承担更高风险
- 了解城镇外区域结构
- 发现通向城镇 B 的路线需求

典型玩法：

- 荒野战斗
- 采集稀有材料
- 遭遇路人、商队、受伤 NPC
- 发现废弃地点
- 修路、清怪、护送

### 5.3 阶段三：交通工具

交通工具不是简单加速按钮，而是跨城镇玩法的门槛和资产。

交通工具属性：

- 速度
- 载货量
- 油耗或维护消耗
- 可通过地形
- 安全性
- 耐久
- 可搭载人数

玩家获得交通工具后，可以：

- 带更多货物去其他城镇
- 接运输委托
- 带 NPC 跨区域
- 前往更远荒野
- 在一天内往返更多地点

### 5.4 阶段四：城镇 B

城镇 B 应该和城镇 A 有明显差异。

示例方向：

- 矿业镇：高利润、高危险、医疗需求高
- 港口镇：贸易强、外来人多、消息复杂
- 边境镇：治安差、战斗委托多、价格波动大
- 商业镇：关系门槛高、投资机会多

城镇 B 的设计重点：

- 不是完全替代城镇 A
- 有自己的核心 NPC 和产业
- 与城镇 A 有商品、委托、消息或人物联系
- 玩家在 A 的名声可以产生影响，但不能完全解决 B 的问题

### 5.5 阶段五：跨城镇经营

长期玩法应该从“我今天去哪赚钱”变成“我如何经营自己的地区网络”。

可能内容：

- A 镇房产
- B 镇仓库
- 车辆升级
- 雇佣 NPC 或临时伙伴
- 跨镇贸易路线
- 地区声望
- 多镇事件链

## 6. 资源与经济

### 6.1 核心资源

| 资源 | 用途 |
| --- | --- |
| 金钱 | 购买物资、修房、买车、投资、治疗 |
| 物资 | 委托、制作、维修、交易 |
| 战利品 | 出售、交付、制作、研究 |
| 情报 | 找人、做决策、解锁委托、影响 NPC |
| 名声 | 解锁委托、价格优惠、NPC 信任 |
| 关系 | 获得帮助、邀请同行、触发私人事件 |
| 时间 | 最重要的限制资源 |
| 体力/健康 | 限制战斗、移动和工作 |

### 6.2 赚钱方式

基础赚钱方式：

- 接委托
- 打工
- 出售战利品
- 出售采集物
- 运输物资
- 倒卖商品
- 完成战斗悬赏

高级赚钱方式：

- 投资店铺
- 经营房产
- 跨城镇贸易
- 雇人采集或运输
- 解锁稀有资源点

### 6.3 价格不应完全静态

价格可以受以下因素影响：

- 城镇需求
- 库存
- 季节
- 道路安全
- 玩家声望
- NPC 关系
- 事件后果

第一版不需要复杂经济模拟，但至少要给商品留下这些字段。

## 7. 委托系统

### 7.1 委托来源

- NPC 主动提出
- 公告板
- 店铺工作
- 道路遭遇
- 荒野事件
- 跨城镇消息

### 7.2 委托类型

| 类型 | 示例 |
| --- | --- |
| 送达 | 把药送给某人 |
| 收集 | 找到指定材料 |
| 战斗 | 清理某处危险 |
| 护送 | 带某人去另一个地点 |
| 调查 | 查清某个传闻 |
| 社交 | 传话、邀请、调解 |
| 经营 | 补货、维修、采购 |

### 7.3 委托应该进入 NPC 世界

委托不是只存在于玩家 UI。

如果 NPC 需要玩家帮忙，NPC 应该记得：

- 自己提出过什么
- 玩家答应了吗
- 截止时间是什么
- 完成/失败了吗
- 结果影响了谁

如果玩家失败，NPC 应该可能：

- 失望
- 另找别人
- 改变计划
- 降低信任
- 自己处理后续

## 8. 战斗和危险

### 8.1 战斗定位

战斗的作用是提供风险、资源和故事后果。

战斗不应该一开始做成庞大的动作系统。第一版可以先做成：

- 小规模实时战斗
- 少量敌人类型
- 明确受伤和消耗
- 简单战利品
- 可撤退

### 8.2 荒野区域

荒野不是空地图。它应该有区域状态：

- 危险度
- 资源类型
- 敌人类型
- 可见度
- 路线安全
- 天气影响
- 发现过的地点

### 8.3 战斗后果

战斗结果应该写入世界：

- 玩家受伤
- NPC 听说玩家击败敌人
- 某条路变安全
- 某个商品供应恢复
- 某个 NPC 对玩家更信任或更害怕

## 9. 大世界结构

### 9.1 推荐结构

不要一开始做完整无缝大世界。

推荐使用“区域节点 + 局部地图”的结构：

- 城镇 A：完整生活模拟地图
- 城镇外道路：可行走或可驾驶区域
- 荒野节点：战斗/采集/事件
- 城镇 B：另一个生活模拟地图

这样可以保留大世界感，同时降低制作成本。

### 9.2 世界节点类型

| 节点 | 功能 |
| --- | --- |
| Town | 城镇生活模拟 |
| Road | 交通、遭遇、运输 |
| Wilderness | 战斗、采集、探索 |
| ResourceSite | 稳定资源点 |
| Ruin | 高风险探索 |
| Camp | 临时休息、商队、事件 |

### 9.3 城镇之间的联系

城镇联系应该通过系统表现：

- 商品价格
- NPC 传闻
- 委托目标
- 运输路线
- 道路危险
- 特产需求
- 亲友关系

## 10. 资产系统

### 10.1 资产类型

| 资产 | 作用 |
| --- | --- |
| 房屋 | 休息、存储、制作、社交邀请 |
| 车辆 | 跨区域、运输、载人、扩大行动半径 |
| 仓库 | 跨城镇经营、囤货 |
| 店铺股份 | 被动收入、关系和经济影响 |
| 装备 | 战斗和探索能力 |
| 工具 | 采集、维修、制作 |

### 10.2 资产应该改变 NPC 反应

例子：

- 玩家买车后，NPC 可能请求搭车。
- 玩家有仓库后，Jack 可能委托玩家帮餐厅囤货。
- 玩家修好房子后，Alice 可能愿意来拜访。
- 玩家战斗装备好后，Tom 可能更愿意让玩家去危险区域取药。

## 11. NPC 与跨城镇系统

### 11.1 NPC 的空间认知

NPC 不应该全知，但可以知道以下内容：

- 自己常去地点
- 自己职业相关地点
- 亲近 NPC 的常见日程
- 听来的消息
- 亲眼看见的事实
- 城镇公告

跨城镇后，NPC 还应该有“远方信息”的概念：

- 听说 B 镇缺药
- 商队说道路危险
- 某人从 B 镇回来
- 玩家带回了 B 镇消息

### 11.2 NPC 跨城镇行为

第一版不需要所有 NPC 都自由跨城镇。

建议分层：

- 核心 NPC：可以在重大事件或计划中跨镇
- 职业 NPC：通常留在本城镇，但可能因职业需求外出
- 背景 NPC：不跨镇或只做抽象迁移

### 11.3 社交计划的跨城镇扩展

现有 social plan 未来需要支持：

- 目标城镇
- 目标地点
- 交通需求
- 是否需要车辆
- 谁负责带路
- 谁已经同意
- 谁可能中途放弃

## 12. AI 使用原则

### 12.1 AI 做什么

AI 负责：

- 解释 NPC 主观判断
- 决定是否在当前条件下行动
- 选择已有任务类型
- 生成自然语言
- 评估关系和记忆的重要性
- 从事实、传闻、感知中推断下一步

### 12.2 AI 不做什么

AI 不负责：

- 编造不存在的地点
- 编造不存在的任务类型
- 直接修改核心数值
- 绕过任务限制
- 决定不可控的复杂行动链

### 12.3 给 AI 的行动边界

AI 应该从固定行为类型中选择，而不是自由写“我接下来做一串事”。

行为类型应该逐步扩展：

- 找人并观察
- 与人谈话
- 跟随某人
- 前往地点
- 参加地点活动
- 工作
- 休息
- 自言自语
- 接受/拒绝社交计划
- 请求玩家带路
- 请求玩家同行
- 进入荒野
- 执行战斗委托
- 运输物资

## 13. 时间系统要求

当前方向已经确定：

- 一年 365 天
- 12 个月
- 每周 7 天
- 四季
- 忽略闰年

时间系统要支持：

- 每日结算
- 周期性日程
- 月度账单
- 季节变化
- 节日
- 延迟任务
- 跨天/跨月/跨季计划

NPC 日程不应该只是每天重复。日程条目需要能按以下条件生效：

- 星期
- 月份
- 季节
- 月内日期
- 年内日期
- 节日覆盖
- 事件覆盖

## 15. 第一版 MVP

### 15.1 目标

做出“玩家在城镇 A 谋生，并能通过一次荒野行动赚到钱”的闭环。

### 15.2 必须有

- 玩家落脚点
- 基础金钱
- 3 到 5 个可卖物品
- 一个公告板或 NPC 委托入口
- 一个荒野小区域
- 一个简单敌人
- 战利品掉落
- 商店出售战利品
- NPC 对玩家完成委托有反应
- 每日结算记录收入和重要事件

### 15.3 暂时不要做

- 完整城镇 B
- 大量敌人
- 复杂装备词条
- 大规模经济模拟
- 所有 NPC 跨城镇自由行动
- 车辆物理驾驶

## 16. 第二版目标

加入“通向城镇 B 的理由”。

内容：

- 需要钱或材料修车
- 城镇 A 有人提到 B 镇机会
- 路线有危险
- 玩家可以接第一个跨区域委托
- B 镇先做小范围可进入区域
- B 镇有至少 2 个核心 NPC 和 1 个独特商品/委托

## 17. 风险提醒

### 17.1 最大风险：系统太多但没有主循环

任何新系统都必须回答：

- 它如何让玩家今天有事可做？
- 它如何影响 NPC 或城镇？
- 它如何带来明天的变化？

答不上来就先不要做。

### 17.2 第二风险：AI 代替规则

AI 可以判断和表达，但核心玩法必须由程序规则承接。

比如：

- “一起吃饭”必须落到地点活动模板
- “去城镇 B”必须落到路线和交通规则
- “战斗委托”必须落到战斗遭遇和奖励
- “投资餐厅”必须落到资产和经济系统

### 17.3 第三风险：城镇 B 抢走城镇 A

跨城镇后，城镇 A 不能废弃。

解决方式：

- A 镇仍有房子和熟人
- A 镇有特产和低成本生活
- A 镇 NPC 会继续产生事件
- B 镇委托可能要求回 A 镇
- 玩家资产分布在多个城镇

## 18. 设计检查清单

新增功能前检查：

- 是否能进入每日循环？
- 是否能产生 NPC 记忆或关系变化？
- 是否有经济价值或信息价值？
- 是否会制造后续事件？
- 是否可被 UI 调试？
- 是否有失败状态？
- 是否能被保存？

新增地点前检查：

- 这个地点有什么合法活动模板？
- 谁会来？
- 什么时候来？
- 玩家为什么来？
- 这里能产生什么委托？
- 这里和其他城镇/地点有什么联系？

新增 NPC 前检查：

- 他的职业是什么？
- 他给世界带来什么功能？
- 他和谁有关系？
- 他在一天、每周、每季有什么不同？
- 玩家为什么要认识他？

## 19. 当前最合理的下一步

短期不要急着做完整大世界。

建议顺序：

1. 加玩家金钱和简单背包。
2. 加物品定义和战利品出售。
3. 加一个最小荒野区域。
4. 加一个敌人和掉落。
5. 加一个 NPC 委托，把战斗/采集结果带回城镇。
6. 让 NPC 对委托结果写记忆、改关系、改后续计划。
7. 再加车辆和城镇间路线。

这条路线最重要，因为它能把“赚钱、战斗、NPC、时间结算”第一次真正连成闭环。
